The web app is React, TanStack Start, TanStack Router, TanStack Query, Tailwind CSS, and shadcn components built on Base UI. [Product](/product) describes each screen, and [Design](/design) describes the visual language.

## Routes

| Route             | Screen                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/`               | Overview for the selected period.                                                                                                        |
| `/spending`       | The spending drill: categories, then counterparties, then the transactions one of them counts.                                           |
| `/ledger`         | Transactions. `?measure=` opens the records behind a number. `/ledger/$id` opens one posting with its meaning and evidence.              |
| `/counterparties` | Counterparties paid or paid by in the period. `/counterparties/$counterpartyId` opens one.                                               |
| `/questions`      | Computed questions, records to check, refunds to link, and movements to confirm.                                                         |
| `/sources`        | Upload, the NetBank download guide, imports that need you, coverage, files, and exports. `/sources/imports/$importId`.                   |
| `/settings`       | Accounts, account history, model usage, identification, the analyst, display, and backups. `/settings/categories` and `/settings/rules`. |

Three server routes pass requests through to the API's HTTP handler without rendering a screen. `POST /uploads` forwards an upload with its headers and body. `GET /sources/$sourceFileId` returns an original file, and `GET /exports/$exportId` returns an export's ZIP.

The top bar links to Overview, Spending, Ledger, Counterparties, Sources, Questions with its open count, Settings, and Upload. The count is `summarizeQuestions` over the whole history, which the root loader reads on every navigation. On a phone, the bar holds the wordmark, Questions, and the menu, which holds the destinations and Settings. Upload is left out there, because Sources in the menu is where you upload, and the bar fits a 375 pixel screen.

The period strip shows on the overview, spending, ledger, and counterparties. Its bars select a month and its year labels a calendar year. Each bar is the month's spending on `/spending` and its outflow elsewhere, from the `measure` the root route passes, and its link reads like "July 2026, $3,000 spent" or "June 2026, no records". The month or year that makes up the whole period carries `aria-current`, set from the period rather than from the address, because a screen without `?period=` still selects the current month. The strip centres the last selected month twice: `ScriptOnce` runs `centreSelected` inline as the last child of the strip's row, after Choose months, so the list already has its final width when the server's HTML reaches the browser and a long history opens on the selected period before the page hydrates. An effect runs it again when the period changes. Choose months, at the end of the strip in `src/components/shell/month-range-picker.tsx`, selects a range of whole months with two selects in a popover, and the strip inks every month in the range. Without a `?period=`, those screens read the current month in the settings timezone, or redirect to the latest month with records when this month has none yet. The overview and spending show `ComparisonControl` from `src/components/comparison-control.tsx` under their titles, and `ComparisonCoverageNote` from `src/components/comparison-coverage.tsx` under it. `IncompleteRecordsNote`, from the same module, names each account with days missing from the period and those days, such as "Everyday card has no records for 11 to 31 August 2026, so August 2026 is incomplete.", from `periodGaps` in `@repo/finance` (see [Analysis](/reference/analysis#periods)). The control's trigger is named for what it does, "Compared with August 2026. Choose another comparison", so it is not mistaken for a strip link to the same month. Its popover offers the period before, the same period last year, and chosen dates on a two-month calendar, and Compare applies the choice. A period of twelve months leaves out last year, because it covers the same dates as the period before. The calendar offers days from the first month with records through today in the settings timezone, marks that day as today, and disables every later day. Both popovers render their heading with `PopoverTitle`, which names the dialog. The calendar selects local-midnight `Date`s, so dates cross in and out of it through local date parts, never through UTC. Its day button in `src/components/ui/calendar.tsx` attaches the focus ref that the shadcn registry version leaves unattached, so the arrow keys move through the days. Adding the calendar again with the CLI undoes this.

Route modules own URLs and loaders. Feature modules under `src/features/` own server functions, query options, and views. Shared controls live in `src/components/ui`, and application-level components such as the period strip, amounts, and provenance marks live in `src/components/`.

An address that names nothing answers with a 404 and `NotFound` from `src/components/not-found.tsx`, the router's `defaultNotFoundComponent`, never with the error page and a 500. A path that matches no route, or names a record the API does not have, such as a transaction ID from before a reimport, gets "There is no page at this address". A value that does not decode, such as `?period=garbage`, `?unspecified=true` without a category, or a path ID that is not an ID, gets "This address has a value Ironcage cannot read". Every route that reads a search or a record from its address sets `onError: addressNotFound` from `src/lib/address.ts`, which turns TanStack's `SearchParamError` and a `notFound` from the API into the router's `notFound()`, and parses each ID in a path with `pathParam`, which throws `notFound()` for a value that is not one. `NotFound` tells an unreadable address by a match's `searchError` or `paramsError`, through `unreadable` in the same module, and links to the overview without the address's period or comparison. When the root's own search cannot be read, the root layout leaves out the top bar and the period strip, because they carry the period into every link they make. On any other address that names nothing, which `namesNothing` finds in the router's matches, it keeps the top bar, whose links carry only the period and comparison, and leaves out the strip, whose links keep the rest of the address and would lead back to the same page. No route has a not-found page of its own, so a `notFound()` below the root shows on the root's match, as a `NotFoundError` in its `error`.

## Design tokens

`src/global-styles/tailwind.css` defines the palette as CSS variables and maps them to Tailwind colors and to shadcn's semantic tokens: `background` is Polymer, `card` and `popover` are Sheet, `foreground` and `primary` are Intaglio. Components use the semantic names. Inflow, outflow, and attention are their own tokens: `inflow`, `outflow`, and `attention`. Category hues come from `src/lib/category-colors.ts`, keyed by top-level category slug.

Archivo is loaded from `@fontsource-variable/archivo` with its width axis. Text styles are Tailwind utilities that set width through `font-stretch`: `type-figure`, `type-figure-s`, `type-title`, `type-heading`, `type-body`, `type-small`, and `type-condensed`. Figures and `tabular` enable `tabular-nums lining-nums`. shadcn components set their text with `text-sm`, so the theme sets `--text-sm` to the Body size, 15 on 24 pixels, and `type-body` reads its size from that token. Tables and controls read as Body without a class of their own.

## State

The period, the comparison, filters, and drill-down path live in validated search parameters, so the back button and bookmarks restore a view. `src/lib/period.ts` defines both keys as Effect schemas:

| Parameter   | Values                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `?period=`  | A month, `2026-08`. A calendar year, `2026`. A range of whole months, `2026-03..2026-05`.                                                                      |
| `?compare=` | `lastYear` for the same period a year earlier, or chosen dates, `2026-03-01..2026-04-14`, both days included. Without it, the comparison is the period before. |

TanStack's search parser reads a typed `?period=2026` as the number 2026, so the year key also decodes an integer. Ranges must not run backwards, and months and dates must exist. A period key is also refused when its months, the months before them, or the same months a year earlier would fall outside years 0001 to 9999, so every comparison the screens name can be resolved. The root route validates both parameters and keeps them on every navigation with `retainSearchParams`. Setting one to `undefined` removes it. `periodKey` writes chosen months as the shortest key: a single month, a calendar year, or a range.

A scope in an address is `ScopeSearch` in `src/lib/scope.ts`, which Spending and the counted ledger both spread into their schemas:

| Parameter        | Values                                                                    |
| ---------------- | ------------------------------------------------------------------------- |
| `?category=`     | A category ID, which includes everything below it, or `uncategorised`.    |
| `?unspecified=`  | `true` for only what sits on the category itself. It needs a category ID. |
| `?counterparty=` | A counterparty ID or `unidentified`.                                      |

Without them, the scope is everything. `searchScope` reads the parameters as a `Scope` and `scopeSearch` writes one back, so every link to a scope goes through the one pair. Spreading the fields leaves a schema's checks behind, so each schema that holds a scope checks `unspecifiedNeedsCategory` itself.

Spending's parameters are `SpendingSearch` in `src/features/spending/search.ts`: the scope, and `?tag=` or `?personalEvent=`, a tag or personal event ID, to count only the spending that carries it. `spendingInput` turns them into `getSpending`'s input with `flowInput`. The route's `loaderDeps` is the whole search, so the period, the comparison, and every part of the scope rerun the loader. `spendingSearch` writes the address of another scope with the same tag or personal event, and the path, the rows, and the header's links all use it.

The ledger's parameters are `LedgerSearch` in `src/features/ledger/search.ts`, a union of two schemas. Without `?measure=`, they are the posting filters and a cursor of posted date and ID. `?categoryId=` takes a category ID or `uncategorised`. With `?measure=`, they open the records behind a number, the counted ledger: `?measure=`, a ledger measure such as `spending`, `income`, or `loanPrincipal`, then a scope, then `?cursor=`, the part, date, and posting ID the next page starts after.

The counted ledger also takes every posting filter that its scope does not set, so category, counterparty, currency, and dates are left out. `countedSearch` writes a scope as these parameters, and `countedLedgerInput` reads them back into `listCountedLedger`'s input with the months from `?period=`, the `analysisBasis` that `flowInput` also sends, and the reporting currency. So the ledger opened from a stream reads the same facts as the stream. The route's loader picks `listLedger` or `listCountedLedger` from `?measure=`. The period strip drops `?cursor=` when it changes the period, because a cursor belongs to the period it was read in. Above the title, the counted ledger names the measure. For spending, it shows the result's `path` through `SpendingPath` instead, so each crumb opens that level of `/spending`, with the tag or personal event filter carried over as `?tag=` or `?personalEvent=`.

Spending's rows open the next level on `/spending`: a category row its subcategories or its counterparties, and a counterparty row its transactions. Which level a scope opens is the API's `level`. The header's path is `SpendingPath` in `src/features/spending/path.tsx`, built on the shadcn `Breadcrumb`, which the counted ledger also renders. Every crumb is a link to its level, narrowed like the page, and the crumb of the open scope is TanStack's active link, marked with `aria-current="page"`. At the `transactions` level, the page renders the counted ledger's rows under the same header, with `countedLedgerPagesQuery`, an infinite query, and Show older. `transactionsInput` builds that input with `countedLedgerInput` from `ledgerSearch`, the address the header's "See these transactions in the ledger" opens, so the list on Spending and the ledger read the same records. For one counterparty, the header also links to that counterparty's page, where its default category is set. The loader loads the breakdown, then the first page of records when the level is `transactions`. When a counted ledger has no rows and no filters, here or on the ledger, it says nothing counts toward the number in the period and points to the period strip. A breakdown with no rows names its scope and does the same.

Questions keep `?kind=`, a `QuestionFilter`, `?scope=period`, and `?importId=`, which narrows the records to check to one file. Without `?scope=`, the screen reads the whole history, as the top bar does. With it, `listQuestions` and `summarizeQuestions` read the retained `?period=` as `periodSelection` sends it, the same selection the overview's Needs your eye counts, so the count it links from is the count the screen opens on. The route's `loaderDeps` include all three and `?period=`. A card's See all opens the ledger at `?questionId=`, which, like `?importId=`, drops the period from `ledgerInput`.

Counterparties keep `?search=` and `?direction=`, `out` or `in`, in the address. The list's shadcn `Tabs` are bound to `?direction=`, and the route's `loaderDeps` include it, so `listCounterparties` reads only the tab's direction.

Filters that choose a reference pass `ReferenceChoice` an `emptyLabel`, such as "All categories", in place of the "None" that editors show.

`resolvePeriodKey` turns a key into its first and last month. Without a key, it takes `currentMonth` in the settings timezone, which Sources also uses to end the whole history. `currentMonth` and the comparison calendar read `today` in the settings timezone, and period resolution reads no other clock. `flowInput` sends the months as `{ kind: "months", from, to }`, with the comparison from `comparisonSelection` and the spending date. The API decides whether the last month is still in progress, so the result, not the browser's clock, says how many days a period has so far. Titles come from `periodLabel` and `monthLabel` in `@repo/finance`. `wholeComparison` gives the whole months a comparison covers, which the control's trigger and options name, so September in progress compares with "the same days of August 2026". Every sentence that states or compares an amount names the dates the result compared, `periodLabel` of its `comparison`: "$310 more than in August 2026" for a whole month, and "$310 more than in 1 to 25 August 2026" while September is in progress, so a partial total never carries a whole month's name.

Query keys are the operation name plus its normalized input. An infinite query adds `"pages"`, so it never shares a cache entry with the single page of the same input. Loaders call `ensureQueryData` so a route renders with data.

Server functions call the API through the typed binding. They validate input with the contracts schemas first. `callApiRpc` in `src/server/api-client.server.ts` creates the stub with `makeRpcStub(env.API, { errors: [FinanceError] })`, so a `FinanceError` arrives with its kind and message, and it times each call out after 10 seconds as `unavailable`.

## Empty states

`periodRecords` in `src/lib/period.ts` says whether a period has anything to show. It is `none` when the monthly flow is empty, which means no file has published a transaction yet, `recorded` when a file covers some day of a month in the period, and `missing` otherwise. It reads each month's `coverage`, not its amounts, because a purchase dated in a month that no file covers still counts in that month. The root route's default period finds the latest month with the same `hasRecords`, so it never opens on a month the screens call empty. The root loads the monthly flow on every screen, so the check costs no extra request.

The overview, spending, counterparties, and the counted ledger load their period query only when the period is `recorded`. The route component checks first and renders a child that reads the query, so no hook runs conditionally. Otherwise the screen shows its title and `NoRecords` from `src/components/no-records.tsx`, which names the period and links to Sources. A period that ends before the current month in the settings timezone asks for "the March 2026 statements", and one that reaches it asks for its CSV and OFX exports so far. With nothing imported, `NoRecords` points to the overview's guide instead. The posting ledger always loads, because your own dates or one file can set its days. Its list, when empty and unfiltered, shows `NoRecords` for a period without records and "No transactions in March 2026." for one with records.

An empty Counterparties tab without a search reads the period's months from the same monthly flow, selected with `periodMonths`. The list holds only counterparties with money in the tab's direction. If any of those months has a non-zero `outflow` or `inflow` in that direction, nobody is identified behind that money yet, and the tab links to identification in Settings and to Questions. Otherwise it says nothing went out, or came in, during the period.

With nothing imported, the overview renders `FirstUse` from `src/features/overview/first-use.tsx`, and its loader reads the imports instead of the flow. `FirstUse` lists the imports that are processing, need review, or failed with `PendingImports`, then the steps from `NetBankGuide`, then a link to Sources. `NetBankGuide` in `src/features/imports/netbank-guide.tsx` uses NetBank's labels as CommBank's help pages name them, such as Microsoft Money for the OFX export, takes the heading level of the section around it, and names each of its sections by its heading. Sources shows the same guide in a shadcn `Collapsible` under the upload, and lists the imports that need you with the same `PendingImports`. `NoRecords` and `FirstUse` render Upload files as `UploadFilesLink`, a TanStack `Link` styled with `buttonVariants`, so assistive technology announces a link.

`useImportCompletion` refetches every query when an import stops processing, then calls `router.invalidate()`. That runs the root's `beforeLoad` again, so the first finished import moves the overview from the current month to the latest month with records.

The shadcn `Empty` in `src/components/ui/empty.tsx` is left aligned, without the registry's dashed box and padding, and its title uses `type-heading`. Adding it again with the CLI undoes this.

## Commands

A write generates a `commandId` with `crypto.randomUUID()` when you confirm, sends it with the expected versions, and shows a pending state until the server responds. On a network failure, Retry resends the same `commandId`. On `stale`, the form keeps your input, shows the current record, and asks again. On success, most writes call `client.invalidateQueries()` with no filter, so every cached query refetches. Uploads, import completion, and source review decisions do the same, and import completion then reloads the route, as [Empty states](#empty-states) describes. A few writes invalidate only the queries they name: display settings, account edits, source removal, export requests, and import retry. A `stale` failure also invalidates every query.

A change that affects money shows a preview first: the affected records, their versions, and the financial impact. Accepting sends those versions. `usePreviewedCommand` in `src/lib/use-previewed-command.ts` holds that protocol for counterparty changes, moving a transaction, and undo: a preview mutation, then a `useCommand` that applies the previewed request with the versions the preview read. A `stale` reply to either refreshes every query and drops the preview, so the next preview reads the records as they are now. A successful apply runs its `onApplied` before the refresh, so a merge can open the counterparty that remains and an undone creation can leave for the list before the removed counterparty's page refetches. `useCounterpartyChange` in `src/features/counterparties/use-counterparty-change.ts` is that hook for `previewCounterpartyChange` and `applyCounterpartyChange`, and it applies the `change` the preview returned.

A counterparty change can move every transaction of a counterparty to another category without changing any total, so `ChangePreview` in `src/features/counterparties/change-preview.tsx` names how many transactions change. When no month's totals move, it says "Changes 42 transactions; totals stay the same". Otherwise it shows `ImpactSummary` from `src/features/events/impact.tsx`, which every preview of a change to money uses. It heads the months that move, such as "Effect on September 2025 to September 2026", with the date basis, the currency, and the calculation time from `instantLabel`. One table follows with a row group per month that moves and, in it, only the totals that move, before and after. Every total of every month, with the spending that rests on the model, sits under Every total, month by month, a shadcn `Collapsible`. The names of the totals wrap, so the three columns fit a dialog at 390 pixels without scrolling sideways. `ChangeDialog` in `src/components/change-dialog.tsx` frames a choice, its preview, and Confirm, which stays off until a preview is shown and says Retry after a lost reply. Take a descriptor, Move to…, merge, a transaction's counterparty, and undo use it. The counterparty's defaults, its reference defaults, and a transaction's "Every Woolworths transaction" preview in place instead. A form that follows a record keeps the version its edits started from and follows the record until you edit it, as the counterparty's defaults do. `CategorySelect` in `src/components/category-select.tsx` offers the tree of the role a form sets, through `roleTree`. When a new role or kind moves the form to the other tree, `categoryForRole` drops the category, so a category the select no longer shows is never saved. The counterparty's defaults, its reference defaults, `IdentifyForm`, and the person answer do this.

Settings saves the model settings from three forms: the usage warning, identification, and the analyst. `useModelSettingsCommand` in `src/features/models/use-model-settings.ts` sends one form's part with the other parts as that form last saw them, and expects their version. An untouched form follows the settings, so saving one part leaves the others ready to save, and one you were editing gets `stale` and offers Keep my edits. `ModelSettingsSave` in `save.tsx` ends each form with its error, its saved note, and its Save button, which takes focus when Keep my edits removes itself. A save puts the settings it returns into the query cache, then refetches every query. Its form becomes untouched but keeps the values it shows. TanStack Form resets an untouched form whenever its default values change, and those come from the settings. If the saved values became the defaults, the older settings still in the form's props would overwrite them on the next render.

`CounterpartyCombobox` in `src/features/counterparties/counterparty-combobox.tsx` finds a counterparty in `getReferenceData`'s list with the shadcn `Combobox`, leaving out the counterparty being changed. It passes `showTrigger={false}`, as Take a descriptor's search does, because the registry's chevron is a button without a name that the shadcn `InputGroupButton` puts in the tab order. The input opens the list on a click, on the arrow keys, and as you type. With `create`, typed text that names none of them is offered as `Create "{text}"`, and a name you already have, in any case, is offered only as that counterparty. The combobox rewrites its text to the selection's label whenever the selection is a new object, so the selected counterparty is the list's own object and a created name is memoized. Take a descriptor searches with `descriptorSearchQuery`, keyed on the deferred text and keeping the last matches as placeholder data, and groups them under Other counterparties and Not identified. It resolves the chosen descriptor against the latest matches, so after a `stale` reply the dialog shows who holds it now and previews again with that version. A transaction's Change reads `PostingDetail.descriptor`, the descriptor of the posting that names the transaction's counterparty. When other transactions would move with it, a `RadioGroup` sends `assignEventCounterparty` for Only this one, or for every transaction a `moveAlias` change that names this transaction and its version, so it moves too even if you had moved it by hand. Both scopes show the counterparty, role, and category the transaction ends up with, and Confirm counts the transactions the preview says change. The transaction's meaning reads its counterparty from a deferred copy of the event, so after a change it shows the transaction as it was until the new counterparty loads, rather than suspending the page and dropping focus.

## Questions

`src/features/questions/page.tsx` renders the Questions screen: the header from `questionSummaryQuery`, the filter chips as a shadcn `ToggleGroup` with a count each, the cards from `questionsQuery`, an infinite query of 25 at a time with More questions, and then the other sections in product order. Refunds to link and movements to confirm read `interpretationReviewsQuery` from `src/features/relationships/queries.ts`, which the loader prefetches. `EventLink` in `src/features/relationships/panel.tsx` renders each proposal's events from that result, so the sections make no request of their own. `affectedMoney` in `@repo/finance` gives the money a header or the overview states, outflow plus inflow, the same figure the API ranks by. Without a question, the header's count gives way to a shadcn `Empty` that says why. The route passes `waiting`, whether suggested subcategories, the open records to check from `openReviewsQuery` in `src/features/review/queries.ts`, or refunds and movements have a row, from the same queries the sections read. Before a file has published a transaction, which `hasImported` in `src/lib/period.ts` reads from the monthly flow the root loads, it says questions appear once your first file imports. It offers Upload files, the same `UploadFilesLink` from `src/components/no-records.tsx` that `NoRecords` and `FirstUse` show, unless the file waits on records to check, which it points to instead. With records, narrowed to a period, it says no question covers a transaction in it. Otherwise it says every transaction has a meaning, and nothing is waiting on you only when `waiting` is false. The chips and the line for a kind with no question show only while some question is open.

`QuestionCard` in `card.tsx` shows the title from `questionTitle`, what the question affects with its dates through `periodLabel`, and in a narrowed list how much of it falls in the period. It says what is proposed and why, shows five samples and See all, and picks the answer for its kind with an exhaustive `switch` over the components in `src/features/questions/answers/`. Each answer has Accept, a shadcn `Collapsible` for Something else, and Skip. An answer that changes a counterparty, a descriptor, or a reference default uses `useAnswer`, which is `useCounterpartyChange` with focus requests. Accept and the answer form both preview, `AnswerPreview` shows `ChangePreview` with Apply, and Cancel returns focus to whichever asked. `IdentifyForm` is a TanStack Form validated by `IdentifyAnswer`, which needs a role for a new person. Its identity field is `CounterpartyCombobox` with `create`, so choosing a counterparty you have moves the descriptor or merges instead of creating a duplicate. An alias answer offers the proposed counterparty there too, because choosing it is the same `moveAlias` as Accept. The person answer scopes Accept and Something else with a `RadioGroup`. `KindSelect` and `RoleSelect` in `src/features/counterparties/fields.tsx` are the kind and role fields of every counterparty form: the identify form, the person answer, and the counterparty page's defaults and reference defaults. `rolesFor` in `choices.ts` leaves transfers out for a person, which "It's me, at another bank" handles by making the person an own account, and `kindRole` drops a role the kind cannot take. A rule conflict and an unresolved event without a descriptor open `EventEditor` in the card, which loads the event with `eventForPostingQuery` only once opened. Closing it returns focus to the button that opened it.

Nothing is removed optimistically. One answer can close several questions, such as every reference of a person, or none, and only the server groups them. The apply mutation stays pending through its refresh of every query, so the card stays disabled until the refetched list drops it. `EventEditor` takes an `onApplied` that runs before that refresh, as `usePreviewedCommand` does.

## History

`src/features/history` renders history. `describeCorrection` and `describeCounterpartyChange` in `describe.ts` word each entry from its before and after records, such as "Default category changed from Groceries to Dining out", "Moved WOOLWORTHS METRO 77 SURRY HILLS from Coles to Woolworths", or, for a transaction returned to its descriptor, "Now follows the bank's description, which names Coles". `scopeLabel` names the transactions it reached: "Only this transaction", "Every Woolworths transaction", or "Every transaction the bank writes as WOOLWORTHS METRO 77 SURRY HILLS". A descriptor reads as the text the bank printed for it, from the entry's `descriptors`, as the descriptor list shows it, and as its alias key only when the bank printed none. The scope adds the number of other texts the bank printed for it, "or 2 similar texts". `HistoryEntry` in `entry.tsx` adds the time from `instantLabel` in `src/lib/time.ts`, which formats with `Intl` in the settings timezone so the server and the browser print the same words. Undo previews with `previewUndoCorrection` or `previewCounterpartyUndo` in a `ChangeDialog`. A counterparty change that cannot be undone says "Undone" or "Changed again later" instead. A correction names counterparties from the history's `names`, and a counterparty change from its own `subjects`.

A transaction's History, in `src/features/events/history.tsx`, reads `getEventHistory`: its corrections and the counterparty changes that changed it, newest first. A counterparty's History reads `listCounterpartyHistory` as an infinite query, 20 entries at a time, with Show earlier changes.

## Amounts

`src/components/amount.tsx` renders every money value from its `Money` minor units through `formatCurrency` in `@repo/finance`, never from a float. Whole-dollar amounts round half away from zero, except an amount under a dollar, which keeps its cents, so a change of 40 cents reads "$0.40" rather than "$0". Outflows show a minus sign and inflows none. The value's color comes from its direction only in the flow and the headline. Tables use Intaglio for every amount so a column reads evenly.

## Charts

The flow diagram uses Recharts' `Sankey` directly, with custom node and link renderers, in `src/features/overview/flow-diagram.tsx`. `flowStreams` in `src/features/overview/flow-streams.ts` turns a flow into the entries it draws. Each entry is a `stream`, a `moneyBack` category, or a `balance`. A spending category whose money back exceeds its spending moves to the in side as "Travel, net money back", a `moneyBack` entry. Kept and From savings are the `balance` entries, from `leftOver` in `@repo/finance`, which the headline also reads, so the diagram shows the headline's figure. The figure's caption counts only `stream` entries as sources and destinations, and names money back apart, because the headline's outflow is already net of it.

Labels sit beside their nodes in margins as wide as the widest label on each side. `useLabelRoom` draws every label into an invisible SVG outside the diagram, measures each with `getBBox`, and measures again once web fonts load, so no label is clipped. The ruler sits outside the part phones hide, so the diagram has its margins when a window widens past `md`.

Every stream is a TanStack `Link` from `streamLink`: a spending category opens `/spending?category=`, and every other stream opens `/ledger` at its scope through `countedSearch`. In the Sankey, the node is the link. Its accessible name reads "Food, $620 went out", and a transparent hit area across its label draws the 2 pixel Intaglio focus ring. The band repeats the link for the pointer with `tabIndex={-1}` and `aria-hidden`, and cancels `mousedown` so a click never focuses a link hidden from screen readers. `accessibilityLayer` is off, so the SVG is not a tab stop, and the tooltip finds its entry from Recharts' `activeIndex` by position, not by name. Kept and From savings are not links. The tooltip, the table, and the phone bars say what each one is.

Below the `md` breakpoint the diagram shows stacked bars instead, and a button shows a table in place of the diagram. Both carry the same links with the same accessible names, so there is no separate screen-reader table, and the income and spending streams both called "Not yet categorised" stay apart. The table has a column header row and one `tbody` per side under a `rowgroup` header, "Came in" or "Went out", and each stream's name is its row header. The hidden Sankey keeps its height on `ResponsiveContainer` rather than on a wrapper, because Recharts warns about a chart with neither width nor height. Charts of months are hand-built HTML bars: the period strip, spending's history chart in `src/features/spending/history-chart.tsx`, the sparklines in `src/components/sparkline.tsx`, and a counterparty's activity chart. Twelve bars render on the server without the measuring pass Recharts needs, and all four draw coverage with `MonthBar` from `src/components/month-bar.tsx`. A `missing` month is a short dashed outline in Slate, never a zero bar. A `partial` month is an outline at the height its records reach. Months outside the selected period are faded. `barScale` sizes bars against the largest positive amount, and money back has no height. `monthAmountText` words each month the same way everywhere: "$400", "$400, some records missing", or "no records". The strip, whose bars have no axis naming the measure, adds what the money did: "$400 spent, some records missing". The history chart is the scope's own `months` series, not the sum of the rows. Each bar carries its words as screen-reader text and a title, and Show as a table swaps the bars for a shadcn `Table` of the same twelve months. A sparkline reads its row's months as one screen-reader sentence, and the breakdown table beside it carries the row's amounts. A counterparty's activity chart in `src/features/counterparties/activity.tsx` draws every month from its first record to its last, with what you paid rising above the line and what you received hanging below it, and Show as a table swaps in the same months with a column for each. Its months carry the coverage of the accounts the counterparty is paid through, and both the bars and the table word them with `monthAmountText`. Chart coordinates may be floats; displayed amounts come from the result's `Money` values.

## Tables

Tables of records use TanStack Table v9 rendered through the shadcn `Table` primitives. Spending's breakdown in `src/features/spending/breakdown-table.tsx` registers only `columnMeta` with `tableFeatures`, so each column carries its class and whether its cells are the row's header. Columns are display columns built with `createColumnHelper` and memoised on the values they read, because a new column array resets the table's models. The first column is the row's header, "Category" or "Counterparty" by level, and stays in view while the table scrolls sideways on a phone. Its name links to the scope the row opens, with the row's `share` as a percent and a bar. Rows arrive sorted from the API and are not sortable. The counterparty list in `src/features/counterparties/list.tsx` is built the same way: the name with its provenance mark as the row's header, the kind, the usual category's swatch, the count of the tab's transactions, and the amount aligned right. Below `sm`, the kind and count columns are hidden. Day-grouped reading lists, such as the ledger, stay lists.

A small fixed summary, with one row per month or per task and nothing to sort or page, uses the shadcn `Table` primitives without TanStack Table: a chart's table view, and model usage by task in `src/features/models/usage.tsx`. It follows the same conventions. Column headers are `scope="col"` in the Small role and Slate, each row's name is a `TableHead` with `scope="row"`, rows do not highlight on hover, and numbers align right. Model usage by task lists each task's calls, its incomplete usage reports, its input and output tokens, and its recorded cost, in small type. The shadcn `Table` sets `text-sm`, which sorts after the `type-small` utility, so a table in small type asks for `type-small!`. A total that no call reported reads Unknown.

## Accessibility

Every action works at 390 pixels wide and by keyboard. Focus returns to the triggering control when a dialog closes. When the change removes that control, the dialog sends focus to what replaces it: `ChangeDialog` takes a `finalFocus`, so Move to… lands on the descriptors heading, and an undone entry focuses its "Undone" status. Chromium drops focus from a control that becomes disabled or leaves the page, so the in-place previews move it on purpose with `useFocusRequest` in `src/lib/use-focus-request.ts`, which focuses an element once it is mounted and enabled. A preview focuses its apply button, and applying or cancelling returns focus to Preview or to the category select. An apply button stays focusable while it saves through Base UI's `focusableWhenDisabled`. `useQuestionQueue` in `src/features/questions/use-question-queue.ts` orders the cards and moves focus on the Questions screen. Skip moves a card to the end for the visit, stores nothing, and focuses the next card's heading. An answer records the questions after it before the list refreshes, and once the refreshed list no longer has the answered question, the nearest of them still there takes focus, or the page title when none is left. More questions stays focusable while it loads, and the first question it loads takes focus. Card headings take focus with `tabIndex={-1}`, and a question about one transaction names it and its date, so no two headings match. A polite live region names the question skipped or answered, each time in a new node, so words heard before are heard again. A transaction's detail is its own route, `/ledger/$id`, not a sheet. Provenance marks and flow streams have text equivalents. A global rule in `src/global-styles/tailwind.css` shortens every animation and transition to 0.01 ms when reduced motion is preferred, which covers the flow's reveal. Tables of amounts scroll within their container rather than the page. A horizontal scroller is `relative`, so the absolutely positioned `sr-only` text inside it cannot widen the page.
