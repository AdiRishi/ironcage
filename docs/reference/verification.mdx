This page holds the test layout, the invariants, and the regression cases with known answers.

Test through public operations with real in-process collaborators and independently known expected values. Replace only true external seams: the model, and Cloudflare bindings when running outside the local runtime. Enrichment tests replace the model with a runner that returns synthetic replies, and no test calls a real model. Before writing a test, name the user-visible regression it catches.

## Layout

| Workspace            | Tool                                                   | Covers                                                                                                                       |
| -------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `packages/finance`   | Vitest and `@effect/vitest`                            | Money, dates, matching, descriptors, interpretation, periods, ledger facts, the flow, and preview measures.                  |
| `packages/contracts` | None                                                   | No tests. Typecheck only.                                                                                                    |
| `workers/processor`  | `@effect/vitest`                                       | Parsers on synthetic files and, locally, on the corpus. The enrichment model client with synthetic replies.                  |
| `workers/api`        | Vitest with `alchemy/Test/Vitest` and a local Postgres | Publication, commands, concurrency, reviews, corrections, relationships, rules, flows, enrichment, exports.                  |
| `apps/web`           | Vitest in Node, and Vitest Browser Mode                | Access validation, RPC error mapping, period keys, and query retry in Node. Dialogs, uploads, and command retry in Chromium. |
| `infra`              | Vitest with `alchemy/Test/Vitest`                      | Deployment stages, and the platform suite in the local Cloudflare runtime, driven over HTTP.                                 |
| `scripts`            | `node --test`                                          | The reference repository sync.                                                                                               |

Browser Mode runs `.test.tsx` files in headless Chromium through the Playwright provider, configured in `apps/web/vitest.config.ts`. Plain `.test.ts` files run in Node.

Tests live under each workspace's `tests/` mirroring `src/`, with their own `tsconfig.json`. `pnpm test` runs everything locally. `pnpm test:unit` skips infra, as CI does. `pnpm test:infra-live` deploys an isolated stage on Cloudflare.

Corpus-backed tests read `fixtures/commbank/` and skip when it is absent, so CI runs on synthetic fixtures. They report aggregate counts only.

## Database

Concurrency and publication tests run on real Postgres. Each test stage starts a fresh Docker Postgres and applies the production migrations to it. The tests cover two overlapping imports publishing at once, two commands claiming the same remaining credit, a repeated command ID, a stale preview, a failure injected before commit, and a committed write whose response is lost.

Migrations are also tested against data. `workers/api/tests/fixtures/populated.json` is a synthetic database captured at one migration: three account kinds, counterparties you set, a rule, a split, a credit link, and a card settlement, all written through the public operations. `workers/api/tests/database/migrations.test.ts` applies migrations up to the captured one with the deployment migrator, loads the rows, applies every later migration, and checks posting totals, allocation conservation, and a month's spending and income counted by hand. Before adding a migration, run `pnpm --filter @repo/api fixture:populated` so the fixture holds data written by the code before it.

## Financial invariants

| Regression to prevent                                                                 |
| ------------------------------------------------------------------------------------- |
| Reupload or overlapping exports duplicate postings.                                   |
| Two real identical rows collapse into one posting.                                    |
| An empty or reused `FITID` causes a false match or rejects valid rows.                |
| A file without an opening anchor is labelled reconciled.                              |
| A failed or repeated publication leaves partial rows.                                 |
| PDF decoding shifts a date, a decimal point, a sign, or a row count.                  |
| A split creates or loses money. A repeated credit link over-applies a credit.         |
| A transfer between owned accounts or a card settlement counts as spending or income.  |
| A payment to a person disappears from spending because the bank called it a transfer. |
| Reinterpretation, enrichment, or a counterparty default overwrites a value you set.   |
| Ledger facts lag behind a correction, a counterparty default, or a reviewed date.     |
| A linked credit stays in a purchase's old category after the purchase changes.        |
| Facts kept by commands differ from facts rebuilt from scratch.                        |
| A headline and its rows come from different data.                                     |
| A change's purchases part and average part do not sum to the change.                  |
| Cash out counts loan interest twice, as spending and again inside the repayment.      |

## Regression cases

Each case has a known answer that does not come from the implementation.

| Case                                                                                                    | Expected                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| OFX row with `DTUSER` and a `Value Date:` suffix in its memo.                                           | `valueOn` set, description without the suffix, the literal memo in `raw`.                                                                          |
| `DTASOF` of `20260831140000`.                                                                           | Closing anchor on 31 August.                                                                                                                       |
| `DTASOF` of `20260831235959`.                                                                           | Closing anchor on 1 September.                                                                                                                     |
| Two identical rows on one day in file A, then file B with the same two rows.                            | Two postings, four observations.                                                                                                                   |
| One row matching two identical postings, with no running balance.                                       | One `duplicate` review item listing both postings.                                                                                                 |
| A reparse that changes a description on an accepted row.                                                | `source_conflict` review item, posting unchanged.                                                                                                  |
| `Transfer to xx5678 CommBank app` where 5678 ends one of your account numbers.                          | Descriptor own suffix `5678`; role `transfer`; no spending.                                                                                        |
| `Transfer To Jane Smith NetBank Rent` for $1,840 with no counterparty.                                  | Role `unresolved`; an `unresolved` question for alias `JANE SMITH`; $1,840 of unresolved outflow.                                                  |
| Jane Smith saved as a `person` with no default.                                                         | A `person` question.                                                                                                                               |
| Jane Smith's default set to Rent with role `purchase`.                                                  | $1,840 spending in Housing, role source `counterparty`, and no question.                                                                           |
| `WOOLWORTHS 1234 SYDNEY AU Card xx1234` and `WOOLWORTHS 5678 SYDNEY AU Card xx1234`.                    | One alias key, `WOOLWORTHS SYDNEY`.                                                                                                                |
| A counterparty default changes after one of its events was corrected by hand.                           | Every event follows the new default except the corrected one.                                                                                      |
| $120 purchase in Clothing in March, $40 refund in April, unlinked.                                      | March Clothing $120, April Clothing −$40.                                                                                                          |
| The same refund linked to the purchase.                                                                 | March Clothing $80, April nothing.                                                                                                                 |
| Cost 30000, two credits of 20000 linked to it at once.                                                  | One link succeeds, the other fails with `conflict`; remaining 10000.                                                                               |
| A dinner with a linked repayment moved from July to August and into Delivery, previewed and then saved. | The preview has July and August, and July spending falls from $5,064.50 to $4,964.50. After saving, each month on the overview equals the preview. |
| A $5.00 refund from Woolworths in August after a $25.00 purchase that month.                            | Woolworths went out $20.00 in August and nothing came in.                                                                                          |
| Split a $150 purchase into $100 and $50, then into allocations totalling $151.                          | The first split keeps spending at $150. The second fails with `conflict`.                                                                          |
| A reviewed correction changes a $4.50 coffee to $5.50.                                                  | The event and its allocation become $5.50, and September's outflow is $5.50.                                                                       |
| The same correction after the coffee was split into $3.00 and $1.50.                                    | The review fails with `conflict` and September's outflow stays $4.50.                                                                              |

## Not built yet

These checks are planned and have no test yet:

- Playwright flows from upload to transaction detail, a question answered, a source review resolved, retry after a failed file, and refresh during processing, at desktop and phone width and by keyboard only.
- An evaluation of enrichment against the real model and your answers.
- An OFX `FITID` reused on a second account. Matching reads only the postings of the file's account, but no test pins it.

## Hosted checks

Local success does not prove hosted behavior. `pnpm test:infra-live` checks bindings, Access, Hyperdrive, R2, and Workflows on a disposable stage.

The platform suite runs the same synthetic upload, command replay, PDF, export,
and source-removal checks locally and when hosted. Its driver reaches the private
API through a service binding. Private corpus cases run only locally. The hosted
suite also checks that application, source, and export requests without a session
redirect to Access. Each test stage is destroyed after the suite.

The separate managed restore suite creates a temporary PlanetScale database,
applies production migrations and a synthetic resolved-review fixture, takes a
backup, and restores it into an independent branch. It checks the exact postings,
saved resolution, and the original file's hash against the independent archive,
then deletes the temporary resources. Run only that drill with
`pnpm --filter @repo/infra test:live tests/database-restore.live.test.ts`.
