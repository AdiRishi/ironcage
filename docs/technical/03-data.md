# Data

What is stored, where, and in what shape. The three tiers are decided ([D9](./00-decisions.md#d9)): **Postgres is the record, Durable Object state is a rebuildable projection, R2 holds blobs.** This chapter specifies the conventions that bind every table, then each schema domain at the level a builder needs — fields and invariants, not full DDL, which lives with the migrations in code.

## Conventions

- **IDs are ULIDs**, generated by the writer before any external call that references them (an intent has its ID before the venue ever hears of it; a decision record has its ID before the model is called). Sortable by creation time, safe to mint anywhere.
- **Time is `timestamptz`, always UTC.** Candle-aligned rows additionally carry the candle's close timestamp as their logical key — the tick's idempotency is keyed on it. Local-time rendering is the app's problem, exclusively.
- **Money is `NUMERIC`, never float, always beside a currency code.** Quantities of assets likewise (`NUMERIC`, asset code). Nothing financial is ever a JavaScript `number` in storage; Effect Schema decodes to a decimal type at the boundary.
- **Append-only means append-only.** Tables marked ⊕ below have no `UPDATE` or `DELETE` path in application code — corrections are new rows that reference what they correct. Mutable tables are the exception and say why.
- **Payloads are `jsonb`, validated at the boundary.** Every `jsonb` column has an Effect Schema in `packages/domain`; a row that fails decoding is a defect, not a shrug.
- **Provenance everywhere.** Any row derived from an external source (a candle, a bank row, a tax event, an AI output) carries where it came from and when it was fetched. Any row derived by our own computation carries the code/config version that computed it.
- **R2 by reference.** Postgres rows point to R2 objects by key; R2 keys embed the ULID of the owning row. Neither store is ever the only holder of the other's existence.

## Postgres schema domains

### Sleeves & mandates

- **`sleeves`** — sleeve ID, name, market, created; current state (`draft | dry_run | live | halted | retired`) and pause flag; pointer to active mandate version. State changes only via `sleeve_transitions` ⊕ (from, to, who/what triggered, why, feed event link) — the table _is_ the lifecycle history the product promises.
- **`mandate_versions`** ⊕ — sleeve ID, version number, the full mandate document (`jsonb`, Schema-validated: purpose, universe, strategy ref + parameters, cadence, capabilities + per-sleeve parameters, capital cap, risk limits, winddown policy, benchmarks), the diff from its predecessor, recorded reasoning, author (operator | proposal ID), and the ceremony record it was approved in. A sleeve's behavior at any past moment is reconstructable by version.

### Trading (the blotter)

The blotter is three append-only tables; positions and equity are _computed_ from them, never stored as truth.

- **`order_intents`** ⊕ for creation, with one mutable column — `state` — advanced only by the owning venue actor ([D8](./00-decisions.md#d8)): `pending → submitted → placed → filled | rejected | canceled | failed`. Fields: intent ID (doubles as the venue client-order ID), sleeve, mandate version, instrument, side, type, quantity/notional, limit price, the **full context that produced it** (strategy signal, each capability's contribution, clamp arithmetic), the cage verdict (every rule checked, pass/fail, distance to limit), and the system-cage reservation ID. A rejected intent is a complete row — rejection is the system working.
- **`orders`** ⊕ — venue order ID, intent ID, venue lifecycle events as received (acknowledged, partial, replaced, canceled), raw venue payload alongside the decoded form.
- **`fills`** ⊕ — fill ID, order ID, quantity, price, **fee amount and fee asset** (Kraken's fee currency varies by order flags — captured, never assumed), venue timestamp, our receipt timestamp, and a `simulated` flag: dry-run and backtest fills flow through this same shape with `simulated = true` and are never conflated with live rows (mode tags survive end-to-end, per the product shell rules).
- **`positions_view`** — a _projection_ (materialized or computed on read; explicitly not the record): current position per sleeve/instrument derived from fills. Rebuildable from scratch at any time; the reconciliation job recomputes it independently before comparing against the venue.

### Capital

- **`capital_acts`** ⊕ — allocation acts (fund / reduce / return), deposits, withdrawals: amount, sleeve (or unallocated), the evidence shown at decision time (report/scorecard references), reasoning, ceremony record. The capital ledger identity (total = unallocated + Σ allocations) is checked by a scheduled assertion, not assumed.
- **`transfers`** ⊕ for creation; `state` column `pending → settled | flagged | dismissed`. Expected amount, source, destination, rail, and — on settlement — the detected venue-side movement it matched. Transfer requests reference the act they serve, so dismissal resolves the act too ([Portfolio](../product/04-portfolio.md)).

### The feed

- **`feed_events`** ⊕ — event ID, timestamp, origin (sleeve | surface | system), category, type, severity, one-line summary, payload (`jsonb`), links (trade story root, report, mandate version, decision record), and the correlation ID grouping one logical action's events (an entry's intent → order → fill chain). Written by each originating actor through its outbox — the feed's completeness guarantee is enforced at the _writer_: emitting the domain row and its feed event is one transaction, so an event cannot be silently skipped.
- **`acknowledgments`** ⊕ — operator acknowledgments of critical events, each itself recorded (who is constant; when matters).

### AI

- **`capability_outputs`** ⊕ — capability, sleeve, output ID, the validated output (`jsonb` — e.g. regime axes per instrument), validation verdict, model + config version used, produced-at, valid-until (the staleness window's edge, precomputed so consumers do arithmetic against one column). The engine reads the latest valid row per capability; absence or staleness resolves to the safe default in code, not in data.
- **`decision_records`** ⊕ ([D12](./00-decisions.md#d12)) — decision ID, capability/agent, what was asked (the question and the material inputs, summarized at decision grain), what was decided, the stated rationale, model, timing, cost if reported, and the AI Gateway log ID(s) linking to deep observability while it exists. Rendered in Activity; kept forever.
- **`scorecards`** ⊕ — per capability, per evaluation window: the counterfactual deltas (P&L, drawdown, cost) versus the no-AI baseline, computed engine-side by the same fill simulator as dry run. The demotion rule reads these rows; so does the living view.
- **`proposals`** ⊕ for creation; `state` advanced by the gate-pipeline Workflow: `submitted → validating → backtesting → walk_forward → shadow → awaiting_approval → approved | rejected | withdrawn`. Fields: proposer (capability), target (mandate diff | strategy variant), the Artifacts commit holding the full proposal bundle ([D13](./00-decisions.md#d13)), each gate's verdict with its artifact pointers, and the ceremony record for the operator's decision.

### Market data

- **`candles`** ⊕ — venue, instrument, timeframe, close timestamp, OHLCV, source (`api | backfill | derived`), fetched-at. Unique on (venue, instrument, timeframe, close_ts); re-fetches must match or are flagged, never silently overwritten.
- **`data_gaps`** — known holes per (instrument, timeframe): detected gaps, backfill acts that closed them (range, source, when — a recorded act per the Workbench spec). Mutable only in the sense that gaps get closed; history of the closing remains.

### Money

- **`bank_accounts`** — account identity, type, latest known balance and its as-of date (the external components of net worth).
- **`bank_transactions`** ⊕ — account, posted date, amount, **raw narrative exactly as imported**, normalized narrative, dedupe key + normalizer version (recomputable — the raw narrative is the durable fact, the key is derived), occurrence index for same-day identical rows, source import ID, category assignment (with `ai | rule | manual` provenance and confidence), and split rows where the operator divided one transaction.
- **`categorization_rules`** — operator-visible rules learned from corrections; editable, versioned by row history.
- **`imports`** ⊕ — one row per import: file name, format, counts (total / new / duplicate / needs-review), and the balance-chain verification result for the overlap window.

### Tax

- **`tax_events`** ⊕ — the canonical event ledger ([Tax](../product/09-tax.md)): event ID, type (acquisition | disposal | transfer | income | withholding | fee | spend | gift | corporate action), timestamp, asset, quantity, **AUD valuation and its rate source**, source system + raw record reference (R2), match group (transfer legs matched across sources), and review state for anything unrecognized or low-confidence.
- **`parcels`** — the CGT unit: asset, acquisition date, cost base, quantity remaining, source event; disposal rows reference the parcels they consumed and the method (FIFO default) that selected them. Mutable only via disposal consumption, which is itself recorded.
- **`tax_source_coverage`** — the gap ledger per source: which time windows were fetched from where; holes render as holes.

### Reports & ceremonies

- **`reports`** ⊕ — type, subject, data window, generated-at, generation config version, R2 key of the rendered body, read/unread. A failed generation is a feed event, and the absent row is the visible fact.
- **`ceremonies`** ⊕ — the decision ceremony's record ([Operations](../product/07-operations.md)): what decision, the evidence presented (by reference — report IDs, scorecard rows, diffs — recorded _as presented_), the plain-language statement of change shown, the operator's written reasoning where required, approve/reject, and timing. Referenced by mandate versions, capital acts, proposals, transitions, and overrides; this table is why no decision is reconstructible only from memory.

## Durable Object state

Each actor's SQLite holds its working set, and each actor implements `rebuild()` — drop local state, reconstruct from Postgres — as a routine operation invoked on first start, after suspected corruption, or on demand. What each holds is listed in [Topology](./02-topology.md); the schema rule here is single: **DO tables are namespaced per concern (`tick`, `outbox`, `inflight`), and no DO table holds anything whose loss would lose information** — the outbox is the one subtlety, and it qualifies because an unflushed outbox row's domain transaction has not been acknowledged as complete until flushed.

## R2 layout

One bucket, prefixed by domain, keys embedding owner ULIDs:

```
exports/{source}/{import_ulid}/...      raw bank/venue/exchange files, exactly as received
candles/{venue}/{instrument}/...        backfill archives (e.g. Kraken quarterly CSVs)
backtests/{run_ulid}/...                inputs manifest, outputs, equity series
reports/{report_ulid}.html              rendered report bodies
proposals/{proposal_ulid}/...           mirrors of Artifacts bundles where needed
tax/{source}/{sync_ulid}/...            raw API pages / statements behind tax events
```

Raw external files are immutable once written. Nothing in R2 is the only record of a fact — Postgres always holds the row that names the key.

## Migrations & retention

Migrations run via Effect's `PgMigrator`, additive-first: new columns nullable or defaulted, destructive changes as deliberate two-step acts (deploy code that stops reading, then migrate), and every migration reviewed like engine code — the schema is load-bearing for every guarantee in this chapter. Retention is the product's rule restated: **nothing is deleted.** At one operator's volume, the entire Postgres record for years fits in single-digit gigabytes; the five-year ATO retention requirement is met by a system constitutionally incapable of forgetting.
