## Implemented

- `/overview` computes historical measures and account coverage in one repeatable-read transaction.
- `/trends` compares fixed, rolling, and calendar periods. Its URL preserves the measure, basis, currency, accounts, filters, alignment, normalization, and grouping.
- `/trends/rows` returns a contributor's current headline and paginated records from the same transaction. Contributions appear beside unchanged bank amounts, with credits and counterpart records.
- `/trends/analyses` lists saved definitions, supports rename and deletion, and opens `/trends/$analysisId`. Opening and explicit refresh resolve relative dates in the settings timezone. Background invalidation does not refresh the displayed result.
- Migration `0014_saved_analyses.sql` stores names, query definitions, grouping, versions, and timestamps. Exports include this table. Financial results are never persisted in a saved analysis.

The `query` JSON column contains `{ query, groupBy }`. The API exposes that value as `definition`. The saved view requests `contributors`, which includes its comparison headline, so the two always share a read transaction.

## Financial checks

A separate spreadsheet reconciled all ten overview values for June 2026 across the four corpus accounts. Its inputs came from independent SQL over posted records, allocations, and linked credits. Spreadsheet formulas calculate costs, surplus, principal reduction, and the income-dependent rate. The workbook stays outside Git. Bank coverage is complete for that month; unresolved interpretations remain visible beside the application totals.

The synthetic delivery example produces July's ten purchases totalling $200 and August's twelve totalling $300. The difference is $100, or 50%, with $45 attributed to frequency and $55 to average payment. The example changes payment accounts between periods without breaking the combined comparison.

Focused tests also cover fractional decomposition, overlapping tag filters, advance bookings with an established purchase date, later refunds, missing coverage, calendar alignment, leap-year clamping, and pagination with equal dates. Account contributors retain their own coverage; postings awaiting interpretation contribute both a count and a magnitude to the warning.

## Writes and date resolution

Real Postgres tests cover saved-definition replay, version conflicts, rename, deletion, and export contents. Reopening a rolling 30-day analysis seven days later advances both dates by seven days. Fixed dates remain unchanged. Sydney midnight on the last day of August and the first day of September selects the correct month.

A correction test moves a purchase between comparison periods and verifies that the next rows read returns matching headlines while preserving the bank amount and posted date. The browser check also changed a synthetic purchase in another tab, then reopened its contributor and observed the corrected total.

## Browser and build checks

Overview, Trends, contributor records, and saved analyses were exercised in the local application. The delivery example, save, rename, open, and refresh flows were checked. The screens were inspected at desktop and 390-pixel phone width; save and rename were also completed by keyboard. Charts retain a table view.

Browser component tests verify that fixed dates can cross the previous interval while being edited and that a saved result changes only after explicit refresh. `pnpm check`, `pnpm typecheck`, `pnpm test`, and the web production build cover this stage and the existing stage 1 to 3 regression suites.
