The web app is React, TanStack Start, TanStack Router, TanStack Query, Tailwind CSS, and shadcn. Stage pages describe each screen; this page describes the mechanics they share. See the [screen designs](/design).

Route modules own URLs and loaders. Feature modules under `src/features/` own server functions, query options, and views. Shared controls stay in `src/components/ui`. Navigation lists only routes that exist.

## State

Filters, periods, and comparison choices live in validated search parameters, so the back button and bookmarks restore a view. Query keys are the operation name plus its normalized input. Loaders call `ensureQueryData` so a route renders with data.

Server functions call the API through the typed binding with the verified identity. They validate input with the contracts schemas before calling.

## Commands

A write from the UI generates a `commandId` with `crypto.randomUUID()` when the user confirms, sends it with the expected versions, and shows a pending state until the server responds. On a network failure, the retry button resends the same `commandId`. On `stale`, the form keeps the user's input, shows the current record, and asks again. On success, invalidate the queries the write affects: the record, the lists that contain it, and any open result that reads it.

Bulk edits and relationship changes in stage 3 show a preview first: the affected records, their versions, and the financial impact. Accepting sends those versions. A preview whose records changed comes back `stale` and is rerun.

## Imports and review

The imports screen polls `getImport` while a file is `processing` and stops when it is not. Counts, failures, and review items come from the server; nothing is inferred client-side. Review items show the literal source text beside each candidate answer.

## Results and charts

From stage 4, a result view shows its measure, period, basis, accounts, calculation time, and coverage before its numbers. Charts use the existing shadcn chart components. Every chart has a title, a text summary, and a table view. Chart coordinates may be floats; displayed amounts come from the result's `Money` values. Selecting a contributor navigates to its rows with the same query in the URL, and the rows arrive with a fresh headline so the two agree.

Estimates are labelled as estimates. Missing coverage is labelled beside the number it affects. Overlapping groups say so.

## Conversation transport

Stage 6 uses the agent SDK's React hook and message components. The web Worker upgrades the WebSocket after validating the Access session and forwards it over the analyst binding with the identity attached. One answer runs per conversation; the send control is disabled until it finishes or the user stops it. Older messages keep their text and calculation time; links open live records.

## Accessibility

Every action works at phone width and by keyboard. Focus returns to the triggering control when a dialog closes. Loading is announced once. Color always has a label or symbol beside it. Reduced-motion preferences disable transitions. Tables of amounts and evidence scroll within their container rather than the page. Use pagination or virtualization when the measured row count needs it.
