Every [stage](/stages) includes a working frontend. Extend the existing React, TanStack Start, TanStack Router, TanStack Query, Tailwind CSS, and shadcn setup. [Workspace](/product/workspace) owns visible behavior. Branding, typography, colors, and screen composition remain open design decisions.

## Routes and state

Stage 1 provides Imports, Transactions, source Review, and account/display settings. Later stages add interpretation controls, historical overview and Trends, Commitments/Forecasts, the analyst, and Insights/inbox in order. Navigation exposes only implemented destinations.

Route modules own URLs and loaders. Feature modules own server functions, query definitions, and views. Common controls stay in the existing UI directory. Keep implemented filters in validated search parameters so browser back and bookmarked views restore the query.

Server functions call the typed financial API with trusted owner context. Shared boundary schemas define money and filters. Query keys contain the operation and its normalized inputs. A global dataset revision is not needed in every key.

## Imports and review

Display per-file upload and processing state, committed counts, and specific unresolved rows. The status read uses stored summaries and platform state where necessary. A failed action offers retry or reupload. Review shows the source and candidate decisions, including declaring a distinct purchase.

Transaction detail reads bank postings independently of interpretation. Stage 3 adds semantic fields and single/bulk category acceptance. Manual categorization remains available when a provider fails or declines to suggest a category.

## Corrections and refresh

Financial edits send a command ID and expected record versions. Show pending state until the server confirms the write. Retry a lost response with the same command ID. A stale edit preserves user input and displays current records for another decision.

Invalidate the affected visible TanStack Query results after success. Saved analyses store definitions and run on open or refresh. Closed saved views do not need background refresh. An earlier analyst message keeps its displayed time and text; a new query reads current data.

## Charts and evidence

Use existing chart components rather than building a plotting framework. Financial totals come from the API. Display coordinates can use finite numbers, but formatted amounts and evidence tables retain the exact monetary contract.

Each chart has a title, textual summary, and table equivalent. Tooltips are supplementary. Selecting a contributor preserves the query and retrieves its current headline and rows together. Show the calculated contribution separately from the bank amount, including linked credits and counterpart evidence. If data changed, refresh the headline with those rows.

Label estimates, observed amounts, source gaps, and overlapping groups. Stage 5 displays cost estimates and known payment dates without probability bands or simulated balances.

## Conversation transport

Stage 6 uses the SDK chat hook and message/tool-result components. The public web Worker authenticates SDK HTTP/WebSocket requests and routes them through the analyst-owned namespace binding. It supplies verified owner metadata on the private hop; browser frames cannot replace it. Verify routing, private access, streaming, reconnect, and stop through that actual binding.

Allow one active answer per conversation. A failed answer can be submitted again. Proposed edits use existing controls or confirmation cards, not automatic financial writes from text. Note changes start a fresh conversation with current notes and leave prior conversations inspectable.

## Accessibility and settings

Every action works on narrow and wide screens and with a keyboard. Preserve selected filters and useful unsaved input after failure. Restore focus after temporary details or edits close. Announce loading without repeatedly interrupting screen-reader users.

Use pagination or virtualization when measured record counts require it. Amounts, evidence, and correction actions remain accessible without horizontal page overflow. Settings shows implemented controls and provider/retention disclosures, never credentials.
