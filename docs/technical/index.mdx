The design extends the existing Alchemy and Effect application platform. PlanetScale Postgres holds financial records, with Cloudflare Hyperdrive connecting the financial API to the database. Financial calculations belong to application services. The AI analyst and web app use those same services.

:::

## Design status

The existing Effect, Alchemy, Cloudflare Worker RPC, TanStack Start, and shadcn platform remains. PlanetScale Postgres and Hyperdrive hold financial records. Use Workflows for background imports and AIChatAgent for stage 6 conversations. Deploy resources only when their stage needs them.

Use libraries before custom implementations. [Ingestion](/technical/ingestion#parsing-libraries) records parser choices and actual corpus evidence. The package catalog and lockfile own installed versions. Model IDs, deployment capacity, and any additional document-input dependency are chosen when the owning feature is implemented and validated against its real workload.

Product pages define the required behavior; stage pages define when it is built. Technical pages preserve exact financial meaning and the smallest implementation needed for those outcomes. Method signatures and exact SQL columns belong to implemented code and migrations, not a parallel catalog of future interfaces.

Failures can require user action. They must preserve accepted data and make repeated financial writes safe. Existing SDK retries are acceptable; custom recovery, model failover, or speculative execution frameworks require a demonstrated product need. Human review is the normal outcome for specific uncertain evidence or classification.

Verify actual amounts, source completeness, duplicate identity, and user corrections through [Acceptance scenarios](/product/acceptance). A library choice or valid model schema alone does not prove the financial behavior. A parser defect or blanket unresolved output remains incomplete work.
