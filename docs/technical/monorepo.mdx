title: Monorepo and ownership
description: Keep domain behavior together and use the existing workspace and binding conventions.
---

The repository uses pnpm, Effect, and Alchemy. Extend that platform rather than replacing it. [Stage boundaries](/technical/stage-boundaries) determines when a capability is introduced. A planned directory is not a reason to create an empty workspace.

## Runtime ownership

| Workspace         | Owns                                                                                                                                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| apps/web          | Authentication at browser entry, TanStack Start routes/server functions, query state, and UI. Stage 6 adds authenticated analyst namespace routing.                          |
| workers/api       | Financial reads and writes, Postgres, source storage, import publication, reviews, and user data controls.                                                                   |
| workers/processor | Library-based extraction and the Workflow that calls financial publication. Later bounded classification and finding work belongs here where background execution is useful. |
| workers/analyst   | Stage 6 AIChatAgent class, conversation tools, explicit note selection, and SDK transport.                                                                                   |

The API owns financial truth. The processor owns parsing. The SDK owns conversation execution and storage. A chart and analyst tool call the same financial query, and neither maintains an independent calculation implementation.

## Shared code

Share boundary schemas where two consumers need them. Share deterministic money and financial calculations between actual callers. Parsers remain in the processor, SQL remains in the API, and UI components remain in the single web application.

A shared AI package is not required before there is meaningful reused logic. Configure the selected SDK beside the document, classification, or analyst behavior. Extract common configuration when it is truly repeated; avoid a generic model execution abstraction.

Use explicit package exports and workspace dependencies. Shared packages cannot import Worker implementations, application routes, or infrastructure. A Worker cannot import another Worker's private repositories. Group modules by domain operation rather than creating a file or package for each RPC method.

## RPC and validation ownership

The existing chain remains:

1. A runtime composes Effect services and returns its handler object.
2. Its Alchemy Worker declaration derives exposed method types and selects public methods explicitly.
3. Typed bindings and Alchemy's RPC bridge infer client arguments, successes, and tagged failures.
4. Browser server functions validate input and inject authenticated context. Model tools use read operations with trusted owner context.

The shared schema defines payload meaning; server code defines method signatures. No additional RPC framework, generated HTTP client, or handwritten duplicate service interface is needed.

Validate external input, stored serialized payloads when decoded, and model output. Internal functions trust decoded types. Ownership, expected record versions, and available credit amounts remain business preconditions checked against current records.

## Infrastructure and storage ownership

Infrastructure remains one Alchemy application with service-owned modules under `infra/src/`. The API owns Postgres/Hyperdrive and source storage. The processor owns Workflows. Stage 6 adds the analyst Durable Object. `infra/src/worker-bindings.ts` composes their capabilities.

The starter's assembly imports runtime entry points to construct Workers. Runtime entry points may use type-only imports of their inferred bindings from `@repo/infra/worker-bindings`. Keep that integration at entry points and platform adapters. Deployment graph values and credentials never enter browser or Worker runtime bundles.

Financial migrations live with the API. Workflow persistence handles its own step state, and AIChatAgent storage holds messages. No extra job database or cross-store recovery service is required. Managed backups and source retention follow [Operations](/technical/operations).

## Build, test, and change ownership

The pnpm catalog and lockfile pin shared dependencies. Every workspace declares its imports. Turborepo follows the dependency graph for checks and builds. Use the existing root scripts, and keep tests with their owning workspace according to [Verification](/technical/verification).

A financial behavior change includes its calculation, API operation, and affected UI in the same stage. Test through public operations with real in-process collaborators; replace true external seams such as model calls. Check actual bindings in the local Cloudflare runtime and hosted behavior where necessary.

A new package needs independent consumers and a useful shared operation. A new runtime needs a distinct execution or storage requirement. File count alone justifies neither.
