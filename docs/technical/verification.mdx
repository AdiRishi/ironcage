Each stage page ends with its verification checklist. This page holds the layout and the cross-stage cases.

Test through public operations with real in-process collaborators and independently known expected values. Replace only true external seams: the model provider, and Cloudflare bindings when running outside the local runtime. Before writing a test, name the user-visible regression it catches.

## Layout

| Workspace            | Tool                                 | Covers                                                                     |
| -------------------- | ------------------------------------ | -------------------------------------------------------------------------- |
| `packages/finance`   | `@effect/vitest`                     | Money, dates, matching, calculations, with fixture tables of known values. |
| `packages/contracts` | `@effect/vitest`                     | Schema round-trips and rejection cases.                                    |
| `workers/processor`  | `@effect/vitest`                     | Parsers on synthetic files and, locally, on the corpus.                    |
| `workers/api`        | `@effect/vitest` with local Postgres | Publication, commands, concurrency, queries.                               |
| `apps/web`           | Vitest Browser Mode                  | Components and server function error mapping.                              |
| `infra`              | `alchemy/Test/Vitest`, Playwright    | Bindings in the local Cloudflare runtime, end-to-end browser flows.        |

Tests live under each workspace's `tests/` mirroring `src/`, with their own `tsconfig.json`. `pnpm test` runs everything locally. `pnpm test:unit` skips infra, as CI does. `pnpm test:infra-live` deploys an isolated stage on Cloudflare.

Corpus-backed tests read `fixtures/commbank/` and skip when it is absent, so CI runs on synthetic fixtures. They report aggregate counts only.

## Database

Concurrency and publication tests run on real Postgres with the production migrations. Cover: two overlapping imports publishing at once, two commands claiming the same remaining credit, a repeated command ID, a stale preview, a failure injected before commit, and a committed write whose response is lost. A read after a commit through Hyperdrive sees the commit.

Migration tests run from empty and from a populated database.

## Financial invariants

| Stage | Regression to prevent                                                         |
| ----- | ----------------------------------------------------------------------------- |
| 1     | Reupload or overlapping exports duplicate postings.                           |
| 1     | Two real identical rows collapse into one posting.                            |
| 1     | An empty or reused `FITID` causes a false match or rejects valid rows.        |
| 1     | A file without an opening anchor is labelled reconciled.                      |
| 1     | A failed or repeated publication leaves partial rows.                         |
| 2     | PDF decoding shifts a date, a decimal point, a sign, or a row count.          |
| 3     | A split creates or loses money. A repeated credit link over-applies a credit. |
| 3     | A transfer or settlement counts as income or spending.                        |
| 3     | Reprocessing or a suggestion overwrites a correction.                         |
| 4     | A headline and its rows come from different data.                             |
| 4     | Contributor totals, counts, and averages disagree with each other.            |
| 5     | A scheduled payment stays in the variable baseline and is counted twice.      |
| 7     | An unchanged finding produces a new notification.                             |

## Regression cases

Each case has a known answer that does not come from the implementation.

| Stage | Case                                                                                                  | Expected                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 1     | OFX row with `FITID` on account A, then the same `FITID` on account B.                                | Two postings. IDs are scoped to the account.                                        |
| 1     | CSV row with a value-date suffix and its OFX row with `DTUSER`.                                       | One posting, `valueOn` set, description without the suffix, both literals in `raw`. |
| 1     | `DTASOF` of `20260831140000` with display timezone Australia/Sydney.                                  | Anchor date 31 August. The timezone does not move it.                               |
| 1     | Two identical rows on one day in file A, then file B with the same two rows.                          | Two postings, four observations.                                                    |
| 1     | File B with one of two identical rows and no running balance.                                         | One `duplicate` review item listing two candidates.                                 |
| 1     | A reparse that changes a description on an accepted row.                                              | `source_conflict` review item, posting unchanged.                                   |
| 3     | Cost 30000, credit 20000 applied, then another 20000.                                                 | Remaining 10000; second application fails with `conflict`.                          |
| 3     | Interest on 31 August, repayment on 2 September, linked.                                              | August cost 280000, September repayment 390000, interest date unchanged.            |
| 3     | Split 10000 into 4000, 3500, 2600.                                                                    | Rejected.                                                                           |
| 4     | January purchase with a February refund linked, spending basis.                                       | January net cost reduced, February account view shows the credit.                   |
| 4     | Daily average over a month with three uncovered days.                                                 | Average unavailable, total and denominator shown.                                   |
| 4     | Rolling 30-day saved analysis opened a week later.                                                    | Dates advanced by seven days. A fixed analysis keeps its dates.                     |
| 5     | The ordinary-cost worked example in [Calculation rules](/technical/calculation-rules#ordinary-costs). | $535.15, components sum exactly.                                                    |
| 5     | Ordinary cost for a period ending in March, with April data present.                                  | April weeks are not in the baseline.                                                |
| 5     | Quarterly levy with a service period.                                                                 | Ordinary cost spreads it by days; the cash calendar keeps the payment date.         |
| 5     | Unmatch an occurrence, rerun matching.                                                                | The event stays unmatched.                                                          |
| 6     | Message "categorize this as strata".                                                                  | No change until the confirmation card is accepted.                                  |
| 7     | Dismiss a finding, rerun the scan with no new data.                                                   | Still dismissed, no inbox entry.                                                    |

## Browser flows

Playwright covers, from stage 1: upload to transaction detail, a review resolution, retry after a failed file, and refresh during processing. Each later stage adds its screens. Every flow runs at desktop and phone width and once by keyboard only.

## Hosted checks

Local success does not prove hosted behavior. `pnpm test:infra-live` checks bindings, Access, Hyperdrive, R2, and Workflows on a disposable stage. The stage report lists any hosted check that could not run.
