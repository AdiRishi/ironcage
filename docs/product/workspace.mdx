Each addition extends the same application. Earlier stages have working navigation and home behavior without links or placeholders for later capabilities. The latest import date and supported coverage remain visible wherever relevant.

## Navigation

The user can reach each implemented destination, inspect its state, and return without losing the relevant selection. Imports explains file processing; Transactions exposes bank history; Review collects specific unresolved evidence or interpretations. Settings holds the controls assigned to the current stage in [Settings and data controls](/product/settings-and-data).

Stage 4 adds an overview of spending, income, cash changes, and repayment effects for a selected period. Stage 5 adds upcoming commitments and stage 7 adds relevant findings. The navigation arrangement and visual composition are design decisions.

## From a chart to an explanation

From stage 4, selecting a chart contribution opens its supporting records with period, date basis, filters, and exclusions intact. Each record distinguishes its calculated contribution from the original bank amount. Related credits and counterpart postings remain inspectable. Stage 5 adds ordinary-cost contributions, labelled as estimates with evidence from payments or schedules.

From stage 6, asking the analyst about a selection retains that scope in the conversation. An answer can include comparisons and evidence. Returning from evidence restores the originating query and position.

Date ranges and implemented filters are reflected in the page URL. A bookmarked view restores its query against current data. Saved analyses, introduced in stage 4, retain query definitions and calculate from current data.

## Screen sizes

Every stage supports the same required actions on desktop and mobile. Source details, filters, review decisions, and corrections remain accessible as their owning stage introduces them. Resizing or navigating between views preserves the relevant selection.

Information never depends on hover alone. Keyboard users can reach controls, evidence, and summaries. Charts have an accessible textual and tabular equivalent from stage 4. Color has accompanying labels or symbols, and transitions respect reduced-motion preferences. Layout, panel arrangement, and control presentation remain open to design.

## Empty, loading, and incomplete states

Before the first import, explain how to add the supported files. Do not show invented financial values. During processing, distinguish accepted uploads from completed imports and restore stored import status after refresh.

From stage 4, an updating result retains the last completed view with its state identified. Incomplete coverage names the missing account or period. Missing information is never zero spending.

A failed request retains selected filters and unsaved input. Repeating a financial write cannot duplicate records or apply a correction twice. Export and analyst retries may start new work. Each owning feature exposes its failures before stage 7 adds inbox aggregation.

## Corrections from any view

Source-review decisions begin in stage 1. Semantic corrections begin in stage 3, default to the selected transaction, and show required impact previews for broader or financial changes. Details retain original source evidence and the current interpretation.

From stage 4, affected results show that refresh is pending until a consistent replacement is available. A view never mixes old and new totals. Stage 6 analyst messages retain their text and calculation time; a new question reads current data.
