Ironcage is a private, responsive web app for one user. It brings supplied financial records into one history, explains spending over time, and supports questions about future commitments and savings.

All capabilities below belong to the current spend-management scope. Statements of product behavior are requirements for the completed application, including behavior described with "can." Examples illustrate those requirements; they do not limit them.

## Product-wide behavior

The same financial question against the same records and assumptions has the same numerical answer in charts, saved analyses, and analyst responses. Each answer states its period, included accounts, measure, and data coverage.

Imports can be repeated safely. Corrections survive later uploads. A failure leaves an explanation and a way to continue, without damaging previously accepted history.

The user can inspect the transactions behind a number and correct an interpretation. Affected views show that an update is pending until a current result is available. Questions name a specific missing fact and its effect on the answer. Import can proceed while unrelated questions remain unresolved.

## Supported financial history

The application supports CommBank spending and savings accounts, offset accounts, credit cards, and home loans. Mortgage payments, strata levies, and changes in payment account are part of the required analysis. Account relationships and effective dates come from source evidence or user confirmation.

Account labels describe where money sits. They do not determine the purpose of every transaction. An expense paid from a savings account remains an expense.

## Product terms

| Term           | Meaning                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| Transaction    | An accepted bank posting, with its account, amount, dates, and supporting source records.                |
| Financial role | How a movement affects costs, income, cash, or debt, such as a purchase, transfer, refund, or borrowing. |
| Category       | The cost classification for a purchase or part of a split purchase.                                      |
| Tag            | An additional purpose or context label. Several tags can apply to the same cost.                         |
| Personal event | A trip, life change, or other named event associated with dates and relevant transactions.               |
| Analysis       | A question and calculation definition, including filters and assumptions, that can be saved for reuse.   |
| Result         | One completed calculation against a particular version of the records.                                   |
| Investigation  | An analyst conversation that can use several analyses and retain their results and explanations.         |

"Spending" means net personal costs unless a view explicitly selects another measure. [Transactions](/product/transactions) defines how purchases, credits, and repayments affect that measure.

## Scope boundary

Recurring manual file import is the input path. Automatic bank feeds are outside the current scope. The app ingests all supplied records, including older statements, and makes actual coverage visible.

This specification does not include executing payments, placing trades, or managing crypto positions. Those belong to later product definitions. Transfers toward an investment remain visible money movements in the spending history.
