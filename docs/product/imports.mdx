Stage 1 imports CommBank CSV and OFX. Stage 2 adds PDF statements.

## Uploading

Drop one file or many. Each file is handled on its own: a bad file does not hold up the others. When a CSV cannot say which account it belongs to, the app asks before processing; OFX and PDF name their account themselves.

Each file shows its progress and then a summary: how many rows were read, how many became new postings, how many matched postings already recorded, and how many need a decision. A file that was already imported says so and links to the earlier import, even under a new name.

A failed file shows why and offers Retry. If the upload itself was cut short, the app asks for the file again. Refreshing the page shows the same state.

## Repeated and overlapping files

The same bytes are one file, whatever they are called. Exports whose date windows overlap add evidence to postings that already exist rather than creating new ones. A CSV, an OFX, and a PDF can all support one posting.

Two real purchases on the same day for the same amount at the same shop stay two postings. When the app cannot tell whether a row is a repeat, it asks rather than guessing either way.

## Questions from the importer

A question shows the source row, what is unclear, and the choices. The user can name the account, accept a decoded value shown beside the original text, point at the posting a row belongs to, say a row is a separate purchase, or keep an accepted posting when a newer read of the file disagrees. Answers stick: reprocessing the file gives the same result.

Rows with an unresolved question stay out of totals until answered. Dismissing a question does not turn a missing amount into zero.

## Coverage

For each file and account the app records the dates it covers and whether the balances reconcile. A file that claims two years but holds two weeks covers two weeks. A period with an opening and a closing balance and no rows between them is a real quiet period; a period with no file is missing data.

## Example

The user drops the August CSV and the August OFX for the spending account. The OFX finishes first and creates 77 postings. The CSV asks for the account, then matches all 77 and creates none. The user drops the same CSV again from a different folder; the app says it was already imported. A September CSV then adds 12 new postings and matches 18 that overlap with August.
