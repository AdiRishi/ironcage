## Accounts and classification

Account labels do not establish transaction purpose. Account role and relationship changes retain their effective dates. Offset/loan relationships arrive in stage 3.

Categories and tags remain editable. Renaming or archiving a referenced category preserves its identity. Accepted merchant aliases can distinguish services. Broad rule changes preview affected records and preserve transaction-specific exceptions. Conflicting rules require a user decision.

## Display and reminders

Default to Australia/Sydney and AUD. Preferences affect subsequent views, not the bank's booked values. A one-currency view identifies excluded currencies without inferred conversion.

From stage 7, an import reminder follows the configured interval and can be disabled. It indicates stale financial data, not a bank connection or a newly observed change.

## AI usage and privacy

Name the configured provider and explain which records or document pages it receives. Gateway routing does not mean inference stays within Cloudflare. Show reported usage, labelled cost estimates, and unknown usage when a failed call provides no report.

The user can disable AI and configure task limits and a usage warning threshold. The threshold can stop new calls after observed usage reaches it, but is not a guaranteed billing ceiling. Delayed reports, unknown charges, or concurrent requests can exceed it. Retrying can incur another charge. Avoid promising an exact spend cap without a separately verified provider capability.

When AI cannot proceed, keep bank records and normal views available. Classification offers direct manual categorization. Document extraction identifies the source needing review or a clearer export.

## Personal notes

Stage 6 provides explicit notes with their supplied account or period scope. Edits and removals change future retrieval. Continue in a fresh conversation after a note change so older transcript text is not silently reused. [Analyst and memory](/product/analyst-and-memory#useful-memory) defines the confirmation and history behavior.

## Export

Stage 2 exports implemented financial records and evidence relationships in a documented machine-readable format. Original source files are a selectable addition. Later stages include interpretations, corrections, saved definitions, schedules, scenarios, notes, findings, and intentions as they arrive.

The download records what it contains and when it was produced. A failed export offers another attempt. Large exports can use the normal background workflow. This is a financial data download, not a synchronized backup of the database, source store, and chat history. Conversation export is not a stage completion requirement.

## Source removal

The confirmation lists affected records and states that only original file bytes will be removed. Accepted transactions, extracted fields, corrections, and evidence relationships remain. Transaction detail marks the original file unavailable; other supporting files remain accessible.

Reuploading the same verified bytes restores source access without adding transactions. A failed removal offers retry and shows the actual availability. Removing financial history or withdrawing transactions is outside this action's scope.

## Retention

Disclose the actual configured database backup retention and original-file copy arrangement from [Operations](/technical/operations#sources-backups-and-retention). Source and note deletion do not promise immediate erasure from retained backups. Temporary downloads expire according to the configured policy.
