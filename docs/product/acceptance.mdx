title: Acceptance scenarios
description: Concrete outcomes, one table per stage group.
---

Each scenario applies from the stage that introduces it and stays a regression afterward. Amounts are fictional. Stage pages carry the engineering checklists; this page is the user's view.

## Importing

| Stage | Scenario                                                 | Outcome                                                                   |
| ----- | -------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1     | Upload the same bytes under a different name.            | Recognized as already imported. No new postings.                          |
| 1     | Upload overlapping exports in either order, or together. | The same postings either way. No false merges.                            |
| 1     | Two same-day purchases, same shop, same amount.          | Both recorded.                                                            |
| 1     | Upload a CSV alone, then an OFX alone.                   | Each works. The CSV asks which account.                                   |
| 1     | An OFX row has no transaction ID.                        | Matched by the rest of its evidence. Nothing collapsed, nothing rejected. |
| 1     | A file named for two years holds two weeks.              | Coverage shows two weeks.                                                 |
| 1     | A row's amount cannot be read.                           | It stays out of totals with a question the user can answer.               |
| 1     | One file in a batch fails.                               | The others complete. The failed one can be retried.                       |
| 1     | The connection drops after a decision is saved.          | Repeating the action returns the saved result. Nothing doubled.           |
| 1     | Refresh while a file is processing.                      | The same state, or a failure with Retry if processing died.               |
| 1     | Open the app without signing in.                         | Refused.                                                                  |
| 2     | One purchase appears in CSV, OFX, and PDF.               | One posting with three sources.                                           |
| 2     | A statement page cannot be read.                         | The page is shown with the question. No value is invented.                |

## Interpreting

| Stage | Scenario                                                 | Outcome                                                             |
| ----- | -------------------------------------------------------- | ------------------------------------------------------------------- |
| 3     | Interpret history imported before stage 3.               | Existing postings gain meaning. No reupload, no new postings.       |
| 3     | The category model fails.                                | Postings unaffected. Manual categorization works.                   |
| 3     | Accept a suggestion, then correct it.                    | The correction wins over later suggestions and rules.               |
| 3     | Import an older overlapping statement after corrections. | Corrections and posting identity survive.                           |
| 3     | $100 on the card, then $100 paid off.                    | Spending $100. Both movements visible.                              |
| 3     | $2000 moved between owned accounts.                      | No income, no spending. A missing other side is shown as missing.   |
| 3     | $300 dinner, $200 reimbursed.                            | Net cost $100. The $200 cannot be applied twice.                    |
| 3     | A refund arrives the month after the purchase.           | The purchase month's net cost falls. The refund keeps its own date. |
| 3     | $3900 repayment, $2800 interest, same month.             | $3900 cash out, $2800 cost, $1100 net principal reduction.          |
| 3     | Interest on 31 August, repayment on 2 September.         | Each month keeps its own. Linking moves no dates.                   |
| 3     | Split a purchase. Preview a rule.                        | Parts add up. Exceptions survive.                                   |
| 3     | Accept a preview after the record changed.               | Nothing changes. The current impact is shown for a new decision.    |
| 3     | Undo a correction.                                       | A new correction restores the old meaning. Sources untouched.       |
| 3     | Rename a category.                                       | Every link intact.                                                  |

## Exploring and planning

| Stage | Scenario                                             | Outcome                                                                          |
| ----- | ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| 4     | Open a contributor after editing elsewhere.          | Headline and rows agree. Same period and filters.                                |
| 4     | Compare a month in progress.                         | Same elapsed days, labelled partial. Missing coverage named.                     |
| 4     | Compare against zero.                                | Amount shown, "new" instead of a percentage.                                     |
| 4     | $200 from ten purchases against $300 from twelve.    | Counts, $20 and $25 averages, $45 from frequency and $55 from price, $100 total. |
| 4     | Two tags on one purchase.                            | Counted once. Overlap labelled.                                                  |
| 4     | A trip with flights paid months earlier.             | Included in the trip. Not double counted.                                        |
| 4     | Purchases move from the deposit account to the card. | The combined trend is continuous.                                                |
| 4     | Daily average with days missing.                     | Unavailable. Total and denominator shown.                                        |
| 4     | Reopen a saved analysis after an import.             | Runs on current data. Fixed dates stay, relative dates move.                     |
| 5     | Confirm a quarterly levy.                            | Paid quarterly in the calendar. Spread across months in ordinary cost.           |
| 5     | Change a commitment's amount from a date.            | Earlier payments unchanged.                                                      |
| 5     | Inspect ordinary-cost contributors.                  | They add up to the headline and name their evidence.                             |
| 5     | Open the outlook with too little history.            | Estimate unavailable. Schedules still listed.                                    |
| 5     | Less delivery, more groceries as a scenario.         | Only the stated changes count. History untouched.                                |
| 5     | Cash calendar beside the estimate.                   | Repayments are movements, not costs. No future balance invented.                 |

## Analyst and follow-through

| Stage | Scenario                                                  | Outcome                                                               |
| ----- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| 6     | Ask a numerical question.                                 | Matches the screen. States time, scope, coverage, evidence.           |
| 6     | Ask for an edit in words.                                 | A card. Nothing changes until accepted.                               |
| 6     | A bank description contains an instruction.               | Treated as text.                                                      |
| 6     | Close the browser mid-answer.                             | Messages restored. A failed answer can be asked again.                |
| 6     | Send while an answer is running.                          | Wait or stop first.                                                   |
| 6     | Remove a note.                                            | Fresh conversation for what follows. Old one readable, not continued. |
| 6     | Connect without signing in.                               | Refused.                                                              |
| 7     | Dismiss a finding, scan again.                            | Still dismissed. No new notification.                                 |
| 7     | A change recurs later, or its evidence is corrected away. | New finding, or the old one closed.                                   |
| 7     | Track fewer deliveries with groceries alongside.          | Both measured against the baseline. Thin evidence called thin.        |
| 7     | A scan fails.                                             | Visible, retryable, nothing changed.                                  |
| 7     | Turn off import reminders.                                | Reminders stop. Everything else continues.                            |
