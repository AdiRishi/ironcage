The repository is a working Cloudflare starter, not a finance application. Stage 1 replaces the starter's feature and data plane while keeping its conventions. Read this page before reading [stage 1](/stages/record-transactions).

## What exists

One Alchemy stack in `infra/` deploys three Cloudflare Workers.

| Worker    | Entry                            | Today                                                                                          |
| --------- | -------------------------------- | ---------------------------------------------------------------------------------------------- |
| Web       | `apps/web/src/worker.ts`         | TanStack Start app. One route that uploads a CSV and shows its column profile.                 |
| API       | `workers/api/src/index.ts`       | Stores uploads in R2 and rows in D1, queues a profiling job, exposes two RPC methods.          |
| Processor | `workers/processor/src/index.ts` | Consumes the queue, profiles the CSV inside a Durable Object session, writes the result to D1. |

The data plane in `infra/src/data-plane.ts` is a D1 database, an R2 bucket with `forceDestroy`, and two Queues. Migrations live in `migrations/` at the repository root. A Durable Object class `CsvProfileSession` is declared in `infra/src/profile-session.ts`. There is no authentication, no Postgres, and no Workflow.

Everything named `artifacts` is the starter feature: `packages/contracts/src/artifacts*`, `workers/api/src/artifacts/`, `workers/processor/src/artifacts/`, `apps/web/src/features/artifacts/`, the routes under `apps/web/src/routes/`, and every test that exercises them under `infra/tests/`, `apps/web/tests/`, `workers/processor/tests/`, and `packages/contracts/tests/`.

## Conventions to keep

These are the parts of the starter that stage 1 builds on.

- **Effect services.** Each Worker composes `Context.Service` classes with layers in its `index.ts` and returns a handler object. Read `.repos/effect/LLMS.md` and the pinned Effect source before choosing an API.
- **Alchemy Worker classes.** `infra/src/api.ts` declares the Worker, picks the exposed methods with `Pick`, and the bridge infers the client types. `infra/src/worker-bindings.ts` composes each Worker's bindings from the data plane.
- **Server functions.** The web app calls the API through TanStack server functions and `apps/web/src/server/api-client.server.ts`. `api-request.ts` maps failures to `AppRequestError`.
- **Test layout.** Tests live under each workspace's `tests/` mirroring `src/`, with a separate test `tsconfig.json`. Infra integration tests use `alchemy/Test/Vitest` with one deploy per file. `apps/web/AGENTS.md` and `infra/AGENTS.md` describe the commands.
- **UI.** shadcn components in `apps/web/src/components/ui`, Tailwind, TanStack Router file routes, TanStack Query with the client in `apps/web/src/lib/query-client.ts`.
- **Tooling.** pnpm catalog in `pnpm-workspace.yaml`, Turborepo, oxlint and oxfmt through `pnpm check` and `pnpm fix`, `pnpm typecheck`, `pnpm test`.

## What stage 1 deletes

Delete the artifacts feature completely rather than adapting it: contracts, API, processor, web feature, routes, tests, the D1 database, both Queues, the Durable Object, and `migrations/`. The starter has no data worth keeping in any environment. Remove `@effect/sql-d1` and queue-related dependencies once nothing imports them.

## What stage 1 adds

| Resource                  | Owner module                   | Purpose                                                                         |
| ------------------------- | ------------------------------ | ------------------------------------------------------------------------------- |
| PlanetScale Postgres      | `infra/src/api.ts`             | Financial records. Reached through a Hyperdrive binding with caching off.       |
| R2 bucket `Sources`       | `infra/src/api.ts`             | Original uploaded files. No `forceDestroy` outside test stages.                 |
| Workflow `ImportWorkflow` | `infra/src/processor.ts`       | Parses one source file and calls the API to publish it.                         |
| Cloudflare Access         | `infra/src/web-application.ts` | Gates the web Worker. The web Worker validates the Access JWT on every request. |
| Migrations                | `workers/api/migrations/`      | Versioned SQL applied by the API's deployment.                                  |

The web Worker, API, and processor keep their names and their Alchemy composition. The API is the only Worker with a database binding. The processor reads sources from R2 and talks to the API through its service binding.

## Private fixtures

`fixtures/commbank/` is git-ignored and holds the real CommBank corpus: 26 CSV and OFX pairs and 47 PDF statements for four accounts, 99 files. `fixtures/README.md` describes the naming. Each CSV and OFX pair covers the same window, and windows overlap on purpose. CSV and OFX must each import on their own.

Never copy private rows into tracked fixtures, test snapshots, or logs. CI runs on synthetic fixtures only.
