## Outcome

Upload CommBank CSV and OFX files and browse the recorded bank history.

Prerequisite: Start with the existing application platform. No spend-management behavior is assumed to have shipped.

## User flows and frontend

- Upload one file or a batch, choose an account when the source cannot identify it, and see per-file progress and supported formats.
- Inspect new and matched transaction counts, specific unresolved rows, and actionable failures. Retry processing or reupload a failed file.
- Resolve account, value, or duplicate questions from the original evidence. Preserve two real identical purchases.
- Search and filter postings by date, account, currency, signed amount, original description, and review state. Open bank fields, extracted rows, and the original file.
- Edit account labels and evidenced roles/effective periods, timezone, and reporting currency. See latest data and source coverage.

The stage is complete only when these flows use real persisted records and work on desktop, mobile, and with a keyboard. Empty, loading, review, and failed states belong to the same implementation.

## Backend and integration

Use csv-parse and an evaluated OFX library with CommBank adapters. Retain original files in private R2 and bank records in Postgres. Publish the accepted rows, evidence, review dispositions, and coverage for each file in one short financial transaction. Source and observation identities make repeated uploads safe. Events, allocations, and categories are not created.

Use managed Workflows and a small import status record. A failed execution can be rerun. Configure managed database backups and an independent original-file copy arrangement, then verify a basic restore before relying on private data. No application backup UI is required.

## Completion evidence

Demonstrate upload through persisted history and source access, with standalone CSV and standalone OFX. Validate every supplied structured file with independently checked amounts, dates, multiplicity, and coverage. Reupload renamed bytes and overlapping exports, including concurrent attempts and a lost publication response. They must preserve accepted records and avoid duplicates. Resolve a specific review item, show one failed file alongside another completed file, and retry it safely.

Verify authentication, the chosen restore procedure, and the connected UI on mobile and with a keyboard.

Preserve earlier stage regressions and report specific unverified external checks. Stop after this stage.

## Excluded

PDF, AI, interpretation records, categories, financial relationship linking, user exports/removal, spending charts, planning, analyst conversations, and findings.
