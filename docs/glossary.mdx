Pages use these words with these meanings and no others. Where a word could mean two things, the glossary picks one and gives the other a different name.

## Records

| Term           | Meaning                                                                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account        | A bank product with a stable identity. Has an account kind, an institution, a label, and a currency.                                                                    |
| Institution    | The bank whose files and descriptions an account uses, such as `commbank`. It chooses the file parsers and the descriptor profile.                                      |
| Account kind   | `deposit`, `card`, or `loan`. Fixed for the life of the account.                                                                                                        |
| Source file    | One uploaded file, identified by the SHA-256 of its bytes. Uploading the same bytes twice yields the same source file.                                                  |
| Import         | One processing run of one source file. Has a status, a summary, and zero or more source reviews.                                                                        |
| Observation    | One transaction row extracted from a source file, with its locator and literal fields. An observation supports at most one posting.                                     |
| Posting        | One transaction the bank booked on one account. The canonical bank record. Several observations from different files can support the same posting.                      |
| Booked amount  | The signed amount the bank booked, in minor units. Positive increases the account balance. Card and loan balances are negative when money is owed.                      |
| Posted date    | The date the bank booked the posting.                                                                                                                                   |
| Value date     | The date CommBank attaches as `Value Date:` in a description or as `DTUSER` in OFX. Stored separately and never used as a purchase date on its own.                     |
| Balance anchor | A dated balance that a source states: a CSV running balance, an OFX `LEDGERBAL`, or a statement's opening or closing balance.                                           |
| Coverage       | The dates a source file establishes for one account, and whether its movements reconcile between two balance anchors.                                                   |
| Source review  | A question the importer cannot answer from the file alone: which account, what value, whether a row is a duplicate, or whether a new reading should replace an old one. |
| Command        | A write with a client-generated command ID. The API stores a receipt so repeating a command returns the first result.                                                   |

## Interpretation

| Term              | Meaning                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Descriptor        | The structured reading of a posting's description: channel, counterparty text, card suffix, own-account reference, location, and foreign amount. Produced by the bank's profile.                                                                                                                                                                                                |
| Channel           | How money moved: `card`, `transfer`, `bpay`, `directDebit`, `directCredit`, `salary`, `cash`, `interest`, `fee`, `loan`, `cardPayment`, or `other`. A channel never decides whether money was spending.                                                                                                                                                                         |
| Counterparty      | Who is on the other side of a posting. Kind `business`, `person`, `ownAccount`, or `institution`. Has a name, an optional parent brand, and a default category.                                                                                                                                                                                                                 |
| Alias             | A normalized descriptor text that resolves to one counterparty. Many aliases can resolve to the same counterparty. An alias is applied, or proposed when the model thinks it belongs to an existing counterparty but is not confident; a proposed alias gives its postings no counterparty until you confirm it.                                                                |
| Financial event   | One economic event grouping one or two postings: a purchase, a transfer, a loan payment. Has a nonnegative magnitude divided into allocations.                                                                                                                                                                                                                                  |
| Financial role    | How an event affects spending, income, cash, and debt: `purchase`, `income`, `transfer`, `cardSettlement`, `borrowing`, `loanPayment`, `refund`, `reimbursement`, `financingCost`, or `unresolved`.                                                                                                                                                                             |
| Allocation        | A nonnegative part of an event's magnitude with a role and, for spending and income, a category. Allocations of one event sum exactly to its magnitude.                                                                                                                                                                                                                         |
| Category          | A node in the taxonomy. Spending categories and income categories form separate trees.                                                                                                                                                                                                                                                                                          |
| Taxonomy          | The category trees. Two levels deep by default, such as Food, then Groceries. Categories keep their IDs through renames and moves.                                                                                                                                                                                                                                              |
| Assignment        | A value set on an event or allocation, such as a role, counterparty, or category, together with its provenance.                                                                                                                                                                                                                                                                 |
| Provenance        | Who made an assignment. A role comes from `user`, `rule`, `bank`, `counterparty`, or `link`, and a category from `user`, `rule`, `counterparty`, or `bank`. A counterparty was set by `user` or `model`, and a model-set counterparty carries the model, its confidence, and its reason. An assignment that comes from a model-set counterparty rests on the model's judgement. |
| Question          | Something the system asks you instead of deciding alone, such as who a descriptor is or whether an alias belongs to an existing counterparty. It shows the proposal, the evidence, and the choices. Questions are computed from current records, not stored.                                                                                                                    |
| Correction        | A user-made assignment on a financial event, kept in history with the prior state. Undo is a new correction. Changes to a counterparty, such as its default category or a merge, are not corrections and have no history yet.                                                                                                                                                   |
| Rule              | A user-accepted condition and action applied to matching events.                                                                                                                                                                                                                                                                                                                |
| Rule conflict     | Two rules that match one financial event and disagree. It becomes a question.                                                                                                                                                                                                                                                                                                   |
| Category proposal | A subcategory the model suggests when no existing one fits. Accepting it creates the subcategory and moves the model's counterparties into it.                                                                                                                                                                                                                                  |
| Credit link       | An amount from a refund or reimbursement applied to a specific spending allocation.                                                                                                                                                                                                                                                                                             |
| Movement link     | The two sides of a transfer, card settlement, borrowing, or loan payment.                                                                                                                                                                                                                                                                                                       |
| Reference default | What payments with one counterparty mean when their reference says so, such as rent to a person who is also repaid for dinners. Outranks the counterparty's default.                                                                                                                                                                                                            |
| Credit proposal   | A refund or reimbursement that looks like it returns one purchase, waiting for you to link or dismiss it. Nothing links until you accept.                                                                                                                                                                                                                                       |
| Movement proposal | Two postings that look like the two sides of one movement, waiting for you to confirm or dismiss. Nothing links until you confirm.                                                                                                                                                                                                                                              |
| Tag               | An extra label on an allocation. Several tags can apply to one allocation.                                                                                                                                                                                                                                                                                                      |
| Personal event    | A named period of life, such as a trip. Allocations can be associated with it. Distinct from a financial event.                                                                                                                                                                                                                                                                 |

## Analysis

| Term              | Meaning                                                                                                                                                                                                                                                                                                              |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Measure           | A named financial quantity, such as spending or income. [Analysis](/reference/analysis) defines each one.                                                                                                                                                                                                            |
| Flow              | Where money came from and where it went in a period: inflows by source, outflows by destination, and own-account movements set aside.                                                                                                                                                                                |
| Ledger fact       | One row of the analysis projection: what one allocation contributes to each measure on each date basis.                                                                                                                                                                                                              |
| Date basis        | `posted` uses posted dates. `spending` uses purchase dates where known, otherwise posted dates.                                                                                                                                                                                                                      |
| Comparison period | The dates a period's figures are compared with: the period before with the same number of months, which is the default, the same period a year earlier, or chosen dates. A period in progress compares with the same days of the period before or of the same period last year. Chosen dates are compared as chosen. |

## Words to avoid

"Transaction" on its own is ambiguous between a posting and a database transaction. Product pages may say transaction to mean posting, because that is what you see. Reference pages say posting, and say database transaction in full.

"Merchant" is replaced by counterparty. A counterparty can be a business, a person, or one of your own accounts.

"Review" on its own is ambiguous. Say source review, question, or movement proposal. The API and the ledger filter still call movement proposals interpretation reviews.

"Event" on its own is ambiguous. Say financial event or personal event.
